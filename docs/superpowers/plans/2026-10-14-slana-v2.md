# Slana v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Solagel into **Slana**. Rooms are always on, entered with a fixed $SLANA fee; eaters take the victim's tokens. Bots carry no value, and a bot kill spills the victim's tokens as loot. A free-mint Metaplex Core **Slana Pass** NFT is the main skin and gates rooms and perks. The UI is rebuilt in the "Kâğıt Bilet" risograph style, and the work ships with player and operator docs.

**Architecture:**
- The Anchor program (`slana`) moves from lamports to an SPL/Token-2022 token through `token_interface`.
- The program holds:
  - per-arena token vaults, plus treasury and season vaults (program PDAs);
  - a fee split on profit only (treasury / season / burn);
  - per-session lamport deposits that reimburse the server's settlement fee;
  - Core-asset parsing for Pass gating, with a per-NFT lock;
  - a free `mint_pass` that CPIs into Metaplex Core `CreateV2`, with commit–reveal of the trait seed.
- The Node server keeps the authoritative 30 Hz simulation. It adds a value ledger with loot, sharded arena instances, practice leagues, NFT verification and metadata endpoints.
- A new `@slana/art` package owns the trait generator and all coin/pass drawing; the web client, server images and the generator CLI share it.
- The React client is rebuilt on a new design system.

**Tech Stack:**
- Anchor 1.2.1 + anchor-spl 1.2.1, Rust 1.97.1, Agave 4.3, LiteSVM 0.17.
- Metaplex Core: program `CoREENxT6tW1HoK8ypY1SxRMZTcVPm7R94rH4PZNhX7d`, instructions hand-encoded.

## Global Constraints

- Names: game **Slana**; token **$SLANA** (display symbol from config, default `$SLANA`).
  - Packages: `@slana/shared`, `@slana/art`, `@slana/sdk`, `@slana/server`, `@slana/web`.
  - Program crate/IDL: `slana`; error enum `SlanaError`; SDK client `SlanaClient`.
- Toolchain is pinned to the versions in Tech Stack. `anchor build --ignore-keys` must work in CI.
- On-chain token amounts are `u64` base units. The SDK uses `bigint` for raw amounts. The server and web use `number` only after `toSafeAmount()` (Task 2) has checked `≤ Number.MAX_SAFE_INTEGER`.
- All token moves use `transfer_checked` or `burn`. Both SPL Token and Token-2022 mints must work. Never transfer lamports out of a token vault.
- Money invariants, every one covered by a test:
  - `payout ≤ vault balance`;
  - the fee is charged on profit only;
  - `fee = treasury + season + burn` exactly, with the rounding remainder going to season;
  - the team never funds player rewards;
  - per arena, `Σ live values + Σ loot + Σ pending payouts = vault balance`.
- Defaults (all configurable):
  - `fee_bps 500`, `pass_fee_bps 200`, split `treasury 5000 / season 3000 / burn 2000`;
  - `settle_fee_lamports 20_000`;
  - `pass_supply 3333`, `pass_per_wallet 1`, `pass_min_tokens 0`;
  - Pass power `PASS_START_MASS_MUL 1.15` and `PASS_CASHOUT_MS 2000`, normal cash-out `3000`;
  - arena instance cap 50 humans, practice instance cap 40.
- UI:
  - No emoji anywhere in the UI; icons are inline SVG from the Task 12 icon set.
  - Fonts: Bricolage Grotesque + DM Mono via @fontsource; colors are the spec §7.1 tokens.
  - Every string in TR and EN; touch targets ≥ 44 px; text contrast ≥ 4.5:1; honour `prefers-reduced-motion`.
- Never commit keypairs or seeds: `keys/`, `*.keypair.json`, `pass-seed*.json`, `.localnet/` stay ignored.
- Third-party program binaries are fetched by `scripts/fetch-programs.sh` into `target/programs/` (ignored), never committed.
- Done means all of these are green:
  - `anchor build && cargo test -p slana`;
  - `pnpm -r typecheck && pnpm -r test`;
  - `pnpm -F @slana/web build`.
- Commit messages end with the two attribution lines from the session instructions.

## Review Focus

1. **Token decimals and supply larger than JS-safe integers.** A Token-2022 mint with 9 decimals and a large supply must not silently lose precision. The server gateway refuses to enable arenas, with a clear log, when the mint's raw supply (base units) exceeds `2^53−1`; the SDK keeps raw amounts as `bigint`. Owning tasks: 2, 7, 10.
2. **Missing or wrong-program token accounts.** The player's ATA may be missing or may belong to the other token program, at both join and settle. The client adds an idempotent ATA create with the mint's token program before `join_arena`. The server's settle adds an idempotent ATA create when the account is missing, so payouts never stall. Owning tasks: 7, 10, 14.
3. **Ticket purchase interrupted** (wallet rejected, blockhash expired, tab closed) **after the session exists on-chain.** The lobby detects the open session and offers "Resume" instead of charging again. The server accepts a join for an existing non-live session; there is no double charge. Owning tasks: 10, 14.
4. **Restart with live stakes and loot on the floor.** Live stakes are auto-cashed-out, loot reappears in the arena's first instance, and the conservation invariant still holds after recovery. Owning task: 8.
5. **One Pass used twice.** The same NFT may be used from two tabs, or sold mid-session and used by the buyer. The second `join_arena_with_pass` fails with "pass in use" while the first session is open. A skin equip by a wallet that no longer owns the asset is rejected at join. Owning tasks: 5, 10.
